# ASCII Virtual Camera

Преобразует живое видео с V4L2-камеры в цветное ASCII-изображение и передаёт его в виртуальную камеру Linux. Видеозвонки, OBS и другие приложения видят обычную камеру с именем `byhinag6shi`.

Во время трансляции можно менять символы, цвет, яркость, размер ячеек и источник видео, а текущий ASCII-кадр сохранять в PNG.

## Возможности

- Преобразование видеопотока в ASCII-графику с цветом камеры.
- Три набора символов: `classic`, `dense`, `binary`; поддерживается свой ASCII-набор.
- Исходные цвета камеры или любой пользовательский RGB-оттенок, зеркало и инверсия.
- Горячая смена визуальных параметров и переключение входной камеры.
- Сохранение текущего ASCII-кадра в PNG.
- Сохранение настроек в конфиг и автоматическое создание/удаление виртуальной камеры.
- Linux x86_64 релизы собираются и публикуются GitHub Actions по git-тегу.

## Требования

Для запуска нужны:

- Linux с V4L2;
- `ffmpeg`;
- модуль ядра `v4l2loopback`;
- `v4l2loopback-ctl` из пакета `v4l2loopback-utils`.

Для более точного автоматического поиска камер и просмотра их режимов рекомендуется также установить `v4l-utils` (`v4l2-ctl`). Без него программа всё равно обнаруживает физические V4L2-устройства, но некоторые камеры могут показывать в списке дополнительные узлы.

### Arch Linux / CachyOS

```sh
sudo pacman -S ffmpeg v4l2loopback-utils v4l-utils
```

Если модуль не собран для текущего ядра, установите DKMS и соответствующие заголовки. Например, для CachyOS:

```sh
sudo pacman -S v4l2loopback-dkms linux-cachyos-headers
```

### Ubuntu / Debian

Включите компонент `universe`, если используете Ubuntu, затем установите нужные пакеты и заголовки текущего ядра:

```sh
sudo apt update
sudo apt install ffmpeg v4l2loopback-dkms v4l2loopback-utils v4l-utils dkms build-essential linux-headers-$(uname -r)
```

Проверьте, что модуль доступен, командой `modinfo v4l2loopback`. Сам модуль и виртуальное устройство программа загружает/создаёт при запуске. Если системная операция требует прав администратора, она запускается через `sudo`.

## Установка из исходников

```sh
git clone https://github.com/hinag6shi/Live-ASCII-Camera.git
cd Live-ASCII-Camera
cargo build --release
./target/release/ascii-virtual-camera
```

Если проект уже скачан, достаточно выполнить `cargo build --release` из его каталога.

## Установка готового релиза

Откройте раздел **Releases** репозитория и скачайте архив вида `ascii-virtual-camera-v0.2.0-linux-x86_64.tar.gz` вместе с файлом `.sha256`.

```sh
sha256sum -c ascii-virtual-camera-v0.2.0-linux-x86_64.tar.gz.sha256
tar -xzf ascii-virtual-camera-v0.2.0-linux-x86_64.tar.gz
./ascii-virtual-camera
```

Готовый бинарник собирается на Ubuntu 22.04 для Linux x86_64 и рассчитан на систему с совместимой glibc (2.35 или новее), V4L2 и `v4l2loopback`. Для других архитектур Linux собирайте проект из исходников.

## Быстрый запуск

Запуск с автоматическим выбором входной камеры и параметрами по умолчанию:

```sh
./target/release/ascii-virtual-camera
```

Программа напечатает путь виртуальной камеры, например `/dev/video12`. В приложении для видеосвязи выберите именно этот `/dev/videoN`/камеру с именем `byhinag6shi`. Если в системе остались устройства от прошлых запусков, не выбирайте старый путь.

Примеры:

```sh
# Плотный ASCII-набор и зеркальное изображение
./target/release/ascii-virtual-camera --ramp-preset dense --mirror

# Янтарный оттенок
./target/release/ascii-virtual-camera --rgb 255 150 35 --saturation 1

# Свой синий оттенок и крупные символы
./target/release/ascii-virtual-camera --rgb 40 130 255 --cell 16

# Явный источник и пользовательский набор символов
./target/release/ascii-virtual-camera --input /dev/video0 --ramp ' .,:;irsXA253hMHGS#9B&@'
```

## Параметры запуска

| Параметр | По умолчанию | Описание |
|---|---:|---|
| `-i`, `--input PATH` | `auto` | Входная камера или путь вроде `/dev/video0` |
| `-o`, `--output PATH` | автоматически | Выходное V4L2-устройство; авто-поиск проверяет `/dev/video10`…`/dev/video63` |
| `--name NAME` | `byhinag6shi` | Имя виртуальной камеры в приложениях |
| `--width PIXELS` | `1280` | Ширина выхода; должна быть чётной для YUYV422 |
| `--height PIXELS` | `720` | Высота выхода |
| `-f`, `--fps FPS` | `30` | Частота кадров |
| `--cell PIXELS` | `8` | Размер ASCII-ячейки; минимум 8 и не больше меньшей стороны кадра |
| `--ramp-preset PRESET` | `classic` | Готовый набор: `classic`, `dense` или `binary` |
| `--ramp CHARS` | — | Свой печатный ASCII-набор от тёмного к светлому; заменяет preset |
| `--saturation N` | `3.5` | Насыщенность от 0 до 5 |
| `--brightness N` | `1.12` | Яркость от 0.5 до 2 |
| `--rgb R G B` | — | Любой цвет символов, три числа от 0 до 255 |
| `--mirror` / `--no-mirror` | выключено | Включить зеркало / отключить зеркало из конфига |
| `--invert` / `--no-invert` | выключено | Инвертировать яркость / отключить инверсию из конфига |
| `--config PATH` | `~/.config/ascii-virtual-camera/config` | Путь к конфигу |

Ширина должна быть чётной, потому что выход передаётся в формате YUYV422. Например, для кадра `458×401` задайте `--width 458 --height 401`. Размер ячейки должен помещаться в обе стороны кадра.

Наборы символов перечисляются от самых тёмных областей к самым светлым. Встроенный шрифт содержит ASCII-глифы, поэтому Unicode-блоки вроде `░▒▓█` в `--ramp` не поддерживаются.

## Управление во время работы

Команды вводятся в терминале; после каждой нажмите Enter.

| Команда | Действие |
|---|---|
| `1`, `2`, `3` | `classic`, `dense`, `binary` |
| `+`, `-` | Сделать символы мельче / крупнее |
| `b`, `B` | Увеличить / уменьшить яркость |
| `s`, `S` | Увеличить / уменьшить насыщенность |
| `m` | Переключить зеркало |
| `i` | Переключить инверсию |
| `c` | Вернуть исходный цвет камеры |
| `v` | Переключить входную камеру на следующую найденную |
| `shot [имя.png]` | Сохранить текущий ASCII-кадр в PNG |
| `save` | Сохранить настройки в конфиг |
| `help` | Показать команды в терминале |
| `q` или Ctrl+C | Корректно завершить работу |

Клавиши — быстрые переключатели. Для точных значений вводите команды целиком:

```text
color 255 80 20       # RGB: красный=255, зелёный=80, синий=20
color camera          # вернуть исходные цвета камеры
color camera          # вернуть исходные цвета камеры
cell 12               # размер ячейки 12 пикселей
brightness 1.35       # допустимый диапазон 0.5–2
saturation 2.4        # допустимый диапазон 0–5
preset dense          # classic, dense или binary
ramp  .,:;ox%#@       # свой набор от тёмного к светлому
mirror off            # также: mirror on или mirror toggle
invert toggle         # также: invert on или invert off
input /dev/video2     # переключить вход на конкретную камеру
shot captures/frame   # сохранить в captures/frame.png
```

RGB задаётся тремя целыми числами от 0 до 255; оттенок применяется к символам с сохранением их яркости. `color camera` или клавиша `c` возвращает исходные цвета. Без имени PNG файл сохраняется в текущую папку под уникальным именем `ascii-camera-<timestamp>.png`.

## Скриншоты PNG

Команда `shot` сохраняет **текущий обработанный ASCII-кадр**, который отправляется в виртуальную камеру. Она не сохраняет исходное изображение веб-камеры. Формат PNG кодирует `ffmpeg` — тот же инструмент нужен для работы самой виртуальной камеры.

```text
shot
shot meeting-frame.png
shot "frame from camera.png"
```

Если расширение не указано, программа добавит `.png`. Другие расширения отклоняются. Существующий файл не перезаписывается: укажите другое имя. Снимок, запрошенный до получения первого кадра, будет сохранён после появления кадра.

## Конфигурация

Настройки загружаются при старте из `~/.config/ascii-virtual-camera/config`. Команда `save` записывает туда выбранную камеру и текущие визуальные параметры, включая свой цвет (`rgb=R,G,B`), а также имя виртуальной камеры, разрешение и FPS. Каталог создаётся автоматически.

Параметры командной строки имеют приоритет над конфигом. Пример явного файла:

```sh
./target/release/ascii-virtual-camera --config ./camera.conf
```

Формат конфигурации — `ключ=значение`, по одной настройке на строку. Если конфиг содержит некорректное значение или повторяющийся ключ, программа сообщает об ошибке до создания виртуальной камеры.

## Устранение проблем

### В приложении чёрный экран или нет видео

1. Сверьте путь выхода в сообщении запуска с выбранной камерой приложения. После старых запусков могут остаться устройства с тем же именем, но без потока.
2. Убедитесь, что выбрана виртуальная камера `byhinag6shi`, а не исходная `/dev/video0`.
3. Проверьте, что входная камера работает: `ffmpeg -f v4l2 -i /dev/video0 -frames:v 1 test.png`.
4. Для доступа к списку возможностей и режимов используйте `v4l2-ctl --list-devices` и `v4l2-ctl --device=/dev/video0 --list-formats-ext`.

### Устройство не удалилось при выходе

Видеозвонок, браузер или OBS могут продолжать держать виртуальное устройство открытым. Закройте приложение, затем выполните команду, напечатанную программой:

```sh
sudo v4l2loopback-ctl delete /dev/video12
```

Замените путь на тот, который был показан при запуске. Удаление устройства, пока его использует другое приложение, запрещено драйвером.

### Нет входной камеры или выбрана не та

Посмотрите устройства командой `v4l2-ctl --list-devices`, затем задайте нужный узел явно, например `--input /dev/video2`. Команда `v` во время работы циклически переключает найденные устройства захвата.

### Неподдерживаемое разрешение

Параметры `--width` и `--height` задают размер виртуального выхода, не режим самой веб-камеры. Список режимов камеры:

```sh
v4l2-ctl --device=/dev/video0 --list-formats-ext
```

## Структура проекта

```text
src/
├── args.rs       # параметры запуска и настройки рендера

```

### Автоматический GitHub Release

Файл `.github/workflows/release.yml` запускается, когда в GitHub отправляется тег `v*`. Он проверяет соответствие тега версии в `Cargo.toml`, собирает Linux x86_64 бинарник, упаковывает его вместе с README, считает SHA-256 и создаёт GitHub Release с автоматически сформированными notes. Workflow запрашивает только `contents: write`, чтобы создать релиз и загрузить файлы.

Чтобы выпустить версию `0.2.0`, сначала измените `version` в `Cargo.toml`, затем соберите проект (это обновит `Cargo.lock`) и зафиксируйте изменения:

```sh
git add Cargo.toml Cargo.lock README.md src .github/workflows/release.yml
git commit -m "feat: add PNG snapshots and modularize source"
git push origin main
```

После этого поставьте и отправьте тег, который **точно совпадает** с версией Cargo:

```sh
git tag -a v0.2.0 -m "v0.2.0"
git push origin v0.2.0
```

Когда GitHub Actions завершится, архив и контрольная сумма появятся на странице **Releases**. Для создания релиза workflow нужен `contents: write`; это разрешение указано в YAML. Если настройки организации ограничивают токен только чтением, владелец репозитория должен разрешить запись в **Settings → Actions → General → Workflow permissions** ([документация GitHub](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#permissions)).

Готовые бинарные релизы пока выпускаются только для Linux x86_64. Linux на других архитектурах можно собрать из исходников при наличии Rust, `ffmpeg` и V4L2-зависимостей.
